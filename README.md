> 촬영할 자리를 찾고, 함께할 사람을 만나다.

**자리온은 코스어와 사진사를 연결하는 촬영 예약·커뮤니티 서비스입니다.**

사진사는 부스를 선점하고 촬영을 모집하며, 코스어는 원하는 사진사와 촬영 조건을 확인해 예약합니다.
촬영 준비부터 예약, 후기 공유까지 한곳에서 이어지는 서비스를 목표로 개발하고 있습니다.

🚧 **현재 개발 중인 프로젝트입니다.**

---

## 📌 프로젝트 소개

코스프레 촬영을 준비할 때는 촬영 공간, 사진사, 시간, 콘셉트 등 여러 조건을 함께 고려해야 합니다.

자리온은 **사진사의 부스 선점**과 **코스어의 촬영 예약**을 연결하고,
커뮤니티를 통해 촬영에 필요한 정보와 경험을 나눌 수 있도록 기획했습니다.

### 주요 목표

- 사진사가 촬영 부스를 선점하고 촬영 정보를 안내할 수 있는 환경 제공
- 코스어가 원하는 촬영 조건을 확인하고 예약할 수 있는 흐름 구성
- 촬영 모집, 준비 질문, 이용 후기를 나누는 커뮤니티 제공
- 사용자 역할에 따른 기능 및 접근 권한 분리

## 🛠 기술 스택 및 사용 의도

### Frontend

| 기술 | 사용 의도 |
| --- | --- |
| **React** | 게시글 목록, 상세 화면, 예약 화면을 컴포넌트 단위로 구성하고 상태 변화에 따라 UI를 갱신합니다. |
| **TypeScript** | 회원, 게시글, 댓글 등의 데이터 구조를 명시하고 타입 불일치로 인한 오류를 줄입니다. |
| **Vite** | 프론트엔드 개발 서버와 빌드 도구로 사용합니다. |

### Backend

| 기술 | 사용 의도 |
| --- | --- |
| **Java** | 회원, 커뮤니티, 예약 관련 비즈니스 로직을 구현합니다. |
| **Spring Boot** | 웹 애플리케이션 설정과 의존성을 관리하고 프론트엔드와 통신하는 API를 구성합니다. |
| **MyBatis** | SQL을 직접 작성하고 조회 결과를 Java 객체에 매핑합니다. 검색, 페이징, JOIN 등의 조회 로직을 관리합니다. |
| **Gradle** | 백엔드 의존성 관리 및 빌드에 사용합니다. |

### Database & Version Control

| 기술 | 사용 의도 |
| --- | --- |
| **MariaDB** | 회원, 게시글, 댓글 등 관계형 데이터를 저장하고 외래 키와 트랜잭션으로 데이터 일관성을 관리합니다. |
| **Git** | 소스 코드의 변경 이력을 기록하고 기능 개발 과정을 관리합니다. |

> 정확한 의존성과 버전은 `frontend/package.json`, `backend/build.gradle`에서 확인할 수 있습니다.

## 🧩 구성 방향

프론트엔드는 HTTP 요청으로 백엔드 API와 통신하며,
백엔드는 MyBatis를 통해 MariaDB의 데이터를 조회하고 저장합니다.

| 계층 | 책임 |
| --- | --- |
| **React** | 사용자 입력, API 요청, 화면 표시 |
| **Controller** | HTTP 요청 및 응답 처리 |
| **Service** | 비즈니스 규칙, 권한 검증, 트랜잭션 관리 |
| **DAO / MyBatis Mapper** | SQL 실행 및 데이터 매핑 |
| **MariaDB** | 데이터 저장 및 관계 관리 |

## 🔐 인증 및 권한 설계

**HttpSession 기반 인증**을 사용합니다.

기능 구현 시 다음 원칙을 적용합니다.

- 작성자 정보는 클라이언트가 전달한 ID 대신 서버 세션에서 확인합니다.
- 게시글과 댓글의 수정·삭제는 서버에서 작성자 권한을 확인합니다.
- 공지 등록과 운영 기능은 관리자 권한을 확인합니다.
- 부스 선점은 사진사 권한을 확인합니다.
- 세션 만료 시 인증이 필요한 API의 응답과 프론트엔드 화면 이동을 연결합니다.

## 🎯 개발 중 중점 사항

### 역할별 권한 분리

화면에서 버튼을 숨기는 것뿐 아니라 백엔드에서도 역할과 작성자를 검증해,
사용자에게 허용된 작업만 처리하도록 구현합니다.

### 예약 데이터의 일관성

동시에 여러 요청이 발생해도 같은 촬영 시간이 중복 예약되지 않도록
트랜잭션, 제약조건 및 필요한 잠금 전략을 검토할 예정입니다.

### 조회 패턴에 맞는 데이터베이스 설계

게시글 최신순 조회, 카테고리 필터, 작성자별 조회에 맞춰 인덱스를 구성하고,
데이터가 증가하면 실행 계획을 확인해 개선합니다.

### 프론트엔드와 백엔드의 책임 분리

프론트엔드는 사용자 경험과 화면 표현을 담당하고,
백엔드는 인증, 권한, 데이터 검증 및 업무 규칙을 담당하도록 구성합니다.
